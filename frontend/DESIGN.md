## 1. 出发点

OPSD 管理的是一组对等的 Linux 服务器：防火墙、容器、数据库、root 终端、定时任务。操作者是运维工程师，打开控制台通常有三种状态：

| 状态 | 他要什么 | 界面应该怎么回应 |
|---|---|---|
| 巡检 | 一眼看出“有没有事” | 首屏给出健康度、异常与待处理项，正常时安静 |
| 处置 | 尽快到达目标对象并执行动作 | 任何对象两次按键内可达；动作就在对象旁边 |
| 确认 | 知道刚才的操作到底生效没有 | 每个写入都有可追踪的结果，结果不明时明确告诉他 |

后端已经把“操作”做得非常严谨：持久受理、请求键幂等、结果未知只查不重放、防火墙限时确认。**前端最重要的职责，是把这套语义诚实、无损地呈现出来**，而不是简化掉。很多控制台在网络抖动时显示“失败”并鼓励重试，这在 OPSD 里是危险的——重试可能让一条 root 命令执行两次。

在此之上，才是“收敛、直观、流畅、优雅”。

## 2. 核心原则

1. **状态诚实优先于界面好看。** 读取中、过期、离线、读取失败、结果未知是不同的状态，不能合并成一个转圈或一个红叉。
2. **收敛：一个概念只出现一种形态。** 所有写入走同一个命令钩子，所有异步结果进同一个操作坞，所有确认用同一个确认框，所有状态色来自同一组语义色。
3. **对象就近操作。** 动作贴着对象出现（行内图标、行菜单、详情侧板），不设独立的“操作页”。
4. **安静的默认，响亮的异常。** 正常运行时界面几乎是灰阶；只有需要人注意的东西才有颜色与动效。
5. **动效只用来解释变化。** 每个动画都回答“东西从哪来、到哪去、变成了什么”，没有纯装饰的动画。
6. **键盘与鼠标同等一等公民。** 命令面板与快捷跳转不是彩蛋，是主要导航方式之一。
7. **前端不发明后端没有的能力。** 例如防火墙待确认只有“确认保留”，没有“立即撤销”接口，界面就不放“撤销”按钮，而是说明“到期自动恢复”。

## 3. 信息架构

### 3.1 导航分组

```
运行   概览 · 节点 · 监控
资源   容器 · 数据库 · 存储
安全   防火墙
工具   终端 · 定时任务 · 操作记录
──────
设置（固定在侧栏底部）
```

- 按“我在做什么”分组，而不是按后端模块分组。“终端”和“操作记录”在 gpt2 中藏在“工具”或抽屉里，t1 提升为一级入口，因为它们是高频的处置与确认动作。
- 9 个一级入口 + 设置，没有二级菜单。二级内容用页内页签或分段控件承载，页签状态写入 URL（`?tab=`），刷新与返回都能复原。
- 节点、数据库集群有独立详情路由（`/nodes/:id`、`/databases/:id`）；容器、任务、操作记录用侧板打开详情，因为它们通常是“看一眼、做一下、关掉”。

### 3.2 详情承载方式的选择

| 方式 | 用在哪 | 理由 |
|---|---|---|
| 独立页面 | 节点、数据库集群 | 内容多、有多个页签、用户会长时间停留、需要可分享的地址 |
| 右侧侧板 | 容器详情与日志、任务编辑与执行记录、操作详情、Compose | 保留列表上下文，看完即走；侧板宽度足够放日志 |
| 居中对话框 | 创建、修改、确认、一次性展示秘密 | 短表单、需要聚焦、必须明确提交或取消 |
| 弹出菜单 | 行内次要动作 | 不打断视线 |

容器详情支持 `?open=` 参数，命令面板搜到容器后直接打开对应侧板。

### 3.3 尚未提供的低频流程

默认前端已是唯一前端和内置界面。`localStorage` 偏好键仍为 `opsd.t1.prefs`,改名会丢失已部署用户的主题与字体偏好,因此保持原样。以下流程步骤多、使用频率低、出错代价高,目前**没有界面入口**,只能通过 `/api/v2` 或 `/api/v2/docs` 完成:

- 接入已有数据库集群（扫描 → 预览 → 提交）、为集群添加成员与代理、代理路由预览与应用；
- 集中监控部署与停用（`PUT /monitoring/config`）；
- OPSD 共享数据：初始化、主备管理节点、节点代理恢复、协调权转交。

补齐它们是下一阶段的首要工作（见第 17 节）。新增时遵循“预览 → 确认 → 持久操作”的既有模式。

### 3.4 路由与服务端白名单

未选择主题时，服务端只为白名单路径返回内置页面（`/`、`/nodes`、`/containers`、`/databases`、`/storage`、`/monitoring`、`/firewall`、`/settings`、`/tools`、`/tools/tasks`、`/tools/terminal`、`/tools/operations`、`/terminal` 及部分前缀），其他路径直接 404。因此工具类页面统一放在 `/tools/` 下；旧地址 `/terminal`、`/tasks`、`/operations`、`/firewall/settings` 由前端带参数与锚点重定向。**新增一级路由时必须同步修改 `backend/internal/control/server.go` 的白名单和 `themes_test.go`。**

内置恢复入口 `/__opsd/builtin/` 下任何路径都返回本界面，此时路由基址为 `/__opsd/builtin`（`src/app/session.tsx` 的 `BUILTIN`）。登录成功一律整页跳转，由服务端决定提供主题还是内置界面；恢复模式下退出、失效与账号修改都保留 `?builtin=1`。

## 4. 交互模型

### 4.1 外壳

```
┌────┬──────────────────────────────────────────────┐
│    │ 面包屑          [ 搜索 / 命令  Ctrl K ]   ☀ 👤 │ 60px 顶栏
│ 68 ├──────────────────────────────────────────────┤
│ px │                                              │
│ 侧 │                 页面内容（独立滚动）             │
│ 栏 │                                              │
│    │                                   ┌────────┐ │
│    │                                   │ 操作坞  │ │
└────┴───────────────────────────────────┴────────┴─┘
```

- **侧栏**：默认 68px 只显示图标，鼠标悬停 140ms 后浮出到 232px（毛玻璃覆盖在内容之上，不推挤布局）；可固定为常开。延迟是为了避免鼠标划过时闪烁。移动端（≤900px）变为抽屉。
- **顶栏**：三栏网格，搜索框固定居中，不受面包屑长度影响。
- **滚动**：只有内容区滚动，侧栏与顶栏固定。换页时滚动回顶部。

### 4.2 命令面板（Ctrl/⌘ + K，或 `/`）

命令面板是 t1 最核心的交互，替代了“先进列表页、再筛选、再点开”的路径。

- 搜索范围：页面、命令（添加节点、切换主题、固定侧栏、打开操作坞、退出登录）、节点、“在某节点打开终端”、容器、数据库集群。
- 匹配：子串优先，其次模糊匹配；连续命中与词首命中加分；标题命中权重高于关键词命中。命中字符用强调色高亮。
- 无输入时展示页面、命令与节点，作为“最近可去的地方”。
- 键盘：↑↓ 选择，Enter 执行，Esc 关闭；鼠标悬停同步选中项。选中背景用共享布局动画在项之间滑动。

### 4.3 快捷跳转

`G` 后 900ms 内按字母：`O` 概览、`N` 节点、`M` 监控、`C` 容器、`D` 数据库、`F` 防火墙、`T` 终端、`K` 任务、`P` 操作记录、`S` 设置。在输入框和终端中不生效。

### 4.4 浮层栈

所有浮层（命令面板、操作坞、对话框、侧板、弹出菜单、确认框）登记到同一个栈。**Esc 只关闭最上层**：在容器侧板里弹出确认框时，按 Esc 只关确认框。焦点在终端内时 Esc 交给 shell，不关闭任何浮层。关闭对话框或侧板后焦点回到打开前的元素。

### 4.5 操作坞

右下角的胶囊是所有异步写入的唯一归宿：

- 平时显示“进行中 N”或“操作”；有待确认或需处理时变为警告色“N 项待处理”。
- 展开后按紧急度排序：待确认 → 需处理 → 进行中 → 已结束。
- 防火墙待确认卡片带倒计时圆环，自己发起的待确认操作会自动展开操作坞。
- 已结束的操作保留 3 分钟供回看，然后自动移除。
- “结果未知”的请求也在这里，只提供“核对原请求”。

把结果集中到一个固定位置，用户不需要记住“刚才那个操作在哪个页面看”。

## 5. 写入与操作语义

这是 t1 与后端契约耦合最深、也最不能出错的部分。

### 5.1 统一的命令钩子 `useCommand`

每个写入都通过 `app/commands.ts` 的 `useCommand`，它负责：

1. 每次意图生成一个请求键（`Idempotency-Key`），同一次点击的重试不换键。
2. 防止重复提交（进行中的命令再次触发会被忽略）。
3. 返回 `Operation`（202 受理）时自动进入操作坞追踪。
4. 按错误类型分流：

| 情况 | 判断依据 | 界面行为 |
|---|---|---|
| 成功 | 2xx | 同步完成提示“已完成”；202 提示“已受理”并追踪 |
| 结果未知（带请求键） | 网络中断、`outcome: unknown`、未声明 `not_accepted` 的 5xx | 登记到操作坞“待核对”，**禁止换键重发** |
| 结果未知（不带请求键） | 同上，但该接口不使用请求键 | 无法按键核对，提示并自动重新读取目标现状 |
| 版本冲突 | 409 / 412 / 428 | 提示并重新读取，草稿保留 |
| 限流 | 429 | 提示等待；同一接口在 `Retry-After` 内直接拒绝本地再发 |
| 其他失败 | 4xx | 显示 Problem 的 `detail` |

### 5.2 核对原请求

`GET /requests/{key}?node_id=` → 有 `operation_id` 则读取原操作并转为普通追踪；`completed` 则提示完成并整体失效缓存；404 只说明“尚未找到”，**不代表不会受理**。待核对请求保存在 `sessionStorage`，刷新页面不丢失，退出登录时清除。

### 5.3 版本条件

- 配置类资源的 GET 返回强 ETag，`getVersioned` 同时取值和 ETag，写入时带 `If-Match`。
- 新建已知 ID 的资源用 `If-None-Match: *`（任务定义、存储目标）。
- `/actions`、`/changes` 一类接口用正文里的 `expected_revision`。
- 删除前先重新 GET 一次拿最新 ETag，避免列表数据过期导致的误判。

### 5.4 操作追踪

- 进行中的操作每 1.5 秒读取一次原 Operation，页面隐藏时暂停。
- 每 12 秒同步一次 `GET /operations?pending=true`，把其他会话或 API 发起的操作也纳入。
- 收到 SSE `operations` 事件时立即同步。
- 进入终态时，按操作的 `subject` 失效相关查询（容器操作完成后容器列表立即刷新），并对自己发起的操作给出结果提示。
- 只接受 `revision` 不倒退的更新，防止旧响应覆盖新状态。

### 5.5 高危动作

- 停止容器、删除规则、修改默认策略、撤销节点、删除库或账号、断开终端：使用确认框，危险动作用红色按钮。
- 不可逆且影响面大的（撤销节点、删除数据库、删除数据库账号）要求输入对象名称才能确认。
- 修改默认入站策略为“丢弃 / 拒绝”时，确认文案明确提醒“可能失去访问”。

## 6. 数据与实时性

### 6.1 读取策略

| 资源 | 刷新方式 |
|---|---|
| 概览 | 每 3 秒 |
| 容器列表 | 每 3 秒 |
| Compose、任务 | 每 5 秒 |
| 防火墙状态、数据库列表与健康 | 每 10 秒 |
| 节点列表、互信状态、监控采集状态 | 每 15 秒 |
| 数据库详情分类（库、账号、代理） | 每 30 秒 |
| 容器日志（跟随时） | 每 2 秒 |
| 其他 | 按需读取，SSE 事件失效 |

- 页面不可见时停止所有周期刷新。
- 列表刷新时保留上一份数据（`keepPreviousData`），不出现闪烁的骨架。
- 首次加载用与最终布局等形的骨架，而不是居中转圈。

### 6.2 事件流

订阅 `/api/v2/events`：

- `invalidate` 事件按资源映射到查询前缀失效（如 `firewall` → 防火墙、概览、互信）。
- 带 `revision` 的事件做去重，不倒退。
- 断线后指数退避重连（1 → 2 → 4 … 最长 15 秒），同时探测会话是否仍有效；重连成功后整体失效活动查询并同步待处理操作。
- 侧栏底部显示连接状态（实时连接 / 正在连接 / 重新连接中）。

事件只用来失效，**从不把事件内容当作数据**，与后端“SSE 是刷新通知，不保存命令结果”的契约一致。

### 6.3 读取状态的表达

后端为多节点资源返回逐节点的 `read`（queued / reading / ready / stale / timeout / error / offline）。t1 的处理：

- 有数据就显示数据，读取状态不覆盖内容。
- 读取失败的节点汇总为一条提示：“部分节点无法读取：A：离线；B：Docker 不可用”。
- 数据库成员只有在拿到真实读数后才判断健康；还没读到时显示“读取中”，而不是“异常”。

### 6.4 实时缓冲

概览每次返回都写入前端环形缓冲（每节点及集群各 48 个点），驱动 KPI 卡片、节点卡片和节点详情的火花线与实时曲线。这让“实时”在打开页面的那一刻就开始积累，不依赖集中监控是否启用。缓冲只在内存中，不持久化。

### 6.5 会话

- 启动时读取 `GET /auth/sessions/current`，拿到 CSRF 令牌后所有非 GET 请求带 `X-CSRF-Token`。
- 任意请求返回 401 时广播会话结束，清空缓存与待核对请求，回到登录入口并带上 `return_to`。
- 登录入口地址保存在 `localStorage`，用户误访问控制台路径时提示正确的安全入口。

## 7. 视觉系统

### 7.1 色彩

- **OKLCH 色彩空间。** 深浅两套主题在感知亮度上一一对应，同一个语义色在两种主题下“看起来一样重”。
- **中性灰阶为主。** 背景、表面、线条、文字各有 3～4 级，全部来自同一个色相（265，略偏冷）的低彩度灰。
- **单一强调色。** 默认色相 166（青绿），用户可在设置里调整色相（`--hue`），按钮、选中态、图表、焦点环全部跟随。第二强调色为色相 +40，只用于渐变（Logo、标题高亮）。
- **语义色固定**：`ok` 绿、`warn` 琥珀、`bad` 红、`info` 蓝、`idle` 灰，每个都有对应的 `-soft` 背景色。语义色不随强调色变化，避免“警告色和强调色撞色”。
- **颜色只用于状态和交互。** 静态内容（标题、正文、图标）不着色。

### 7.2 层次

| 层 | 用途 | 处理 |
|---|---|---|
| `--bg` | 页面底色 | 最暗 |
| `--bg-sunk` | 输入框、代码块 | 比底色更低，表示“可以往里填” |
| `--surface` | 卡片 | 1px 内描边 + 极轻阴影 |
| `--surface-2/3` | 悬停、选中、嵌套 | 逐级提亮 |
| `--glass` | 浮层（命令面板、操作坞、菜单、通知、展开的侧栏） | 半透明 + 背景模糊 |

用 1px 内描边（`inset box-shadow`）而不是 `border` 画卡片边界：不占布局尺寸，叠加阴影时不会出现双线。

页面右上角有一团极淡的强调色光晕，给深色界面一点空间感，浅色主题下减弱。

### 7.3 字体

- 界面：Inter Variable；等宽：JetBrains Mono Variable。均通过 `@fontsource-variable` 打包，按 Unicode 区段拆分加载。
- **中文不打包字体**，回退到系统字体（PingFang SC / 微软雅黑 / Noto Sans SC）。gpt2 打包了约 25MB 的中文字体，t1 的取舍是：系统中文字体质量已经足够，体积优先。
- 数字一律等宽数字（`tabular-nums`），刷新时数值不会左右跳动。
- 标识、地址、命令、镜像名用等宽字体。

### 7.4 尺寸

| 令牌 | 值 |
|---|---|
| 间距 | 4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 |
| 圆角 | 6（标签）· 9（按钮、输入框）· 12（提示框）· 16（卡片）· 22（对话框、侧板、浮层） |
| 控件高 | 36（紧凑 32）；小按钮 30；大按钮 44 |
| 表格行高 | 44（紧凑 38） |
| 侧栏 | 68 / 232 |
| 顶栏 | 60 |
| 内容最大宽 | 1480 |

圆角按层级递增：越是“容器”圆角越大，越是“内容”圆角越小。紧凑密度只改控件和行高，不改字号。

## 8. 动效系统

### 8.1 原则

- **弹簧优先于时长曲线。** 位移、缩放、布局变化用弹簧，可被打断、自然衔接；只有淡入淡出用固定时长。
- **进场慢、退场快。** 进场 300～500ms，退场 120～200ms。用户关掉一个东西时不想等。
- **动的是“变化的那部分”。** 共享布局动画让选中指示器从旧位置滑到新位置，而不是整组重绘。
- **尊重系统设置。** `MotionConfig reducedMotion="user"` 加 CSS 全局降级，开启“减少动态效果”时所有动画近乎瞬时。

### 8.2 参数

| 场景 | 参数 |
|---|---|
| 选中指示器（导航、页签、分段控件、设置导航、终端标签） | 弹簧 stiffness 520 / damping 40 / mass 0.9 |
| 命令面板选中项 | 弹簧 700 / 45（跟手更紧） |
| 弹出菜单 | 弹簧 600 / 38，缩放 0.96 → 1 |
| 对话框 | 弹簧 420 / 34，缩放 0.96 + 上移 12px |
| 侧板 | 弹簧 380 / 38，从右侧 48px 滑入 |
| 命令面板 | 弹簧 520 / 36，下落 14px |
| 通知 | 弹簧 520 / 34，从下方 24px 升起 |
| 操作坞 | 弹簧 440～460 / 32～36 |
| 页面切换 | 0.38s，上移 10px 淡入，曲线 (0.22, 1, 0.36, 1) |
| 列表入场 | 每项间隔 35ms，单项 0.42s 上移 8px |
| 数字变化 | 650ms，四次方缓出 |
| 进度条、圆环 | CSS 过渡 700～900ms |

### 8.3 有意设计的几个动效

- **主题切换**：支持 View Transitions 的浏览器里，新主题从点击位置以圆形扩散覆盖旧主题；此时不叠加全局颜色过渡，避免两层动画打架。
- **登录失败**：卡片左右抖动一次（方向交替），比红字更快被注意到。
- **在线状态**：在线节点的状态点有缓慢的涟漪；离线、异常节点没有。动效本身就是“活着”的信号。
- **待确认**：操作坞卡片外圈发光 + 倒计时圆环每 250ms 更新。
- **执行中**：操作卡片底部一条不确定进度的流光；只在“确实在执行”时出现。
- **火花线**：曲线末端有一个呼吸的点，表示“这是最新值”。
- **展开折叠**：高度从 0 到 auto 的过渡用于步骤列表、编辑区、未保存提示，不用于大块内容。

### 8.4 不做的动效

- 不做页面整体的滑动转场（会让人误以为有前进后退的层级关系）。
- 不做数据刷新时的闪烁高亮（每 3 秒刷新一次会变成持续的视觉噪音）。
- 不做骨架以外的“加载动画”。

## 9. 组件约定

全部组件在 `src/ui/kit.tsx`，不引入第三方组件库。原因：需要完全控制动效与浮层栈；组件数量有限（约 30 个）；避免像 gpt2 那样受组件库角色变量和结构约束。

| 组件 | 约定 |
|---|---|
| `Button` | `primary` 每个区域最多一个；`danger` 只用于不可逆动作；`busy` 时显示旋转图标并禁用 |
| `IconButton` | 必须有 `label`（同时作为 `aria-label` 和 `title`） |
| `Badge` / `Dot` | 状态唯一表达方式，颜色来自 `Tone`；`Dot live` 只用于“正在运行 / 在线” |
| `Notice` | 页面级提示；`tone` 决定图标与配色；操作按钮放右侧 |
| `ErrorNotice` | 读取失败；显示 Problem 的 `detail` 与请求 ID 前 10 位，附重试 |
| `Card` / `CardHead` | 内容分组；`hoverable` 只用于整卡可点击的场景 |
| `Segmented` | 2～6 个互斥选项、需要一眼看到全部时使用；可带计数 |
| `Tabs` | 页面内主分区，状态写 URL |
| `Dialog` / `Sheet` | 见 3.2；都接入浮层栈与焦点恢复 |
| `Menu` / `Popover` | 行内次要动作；滚动或窗口变化时自动关闭 |
| `Ring` / `Meter` / `Ticker` | 计量；百分比超过 75% 变警告色，超过 90% 变危险色 |
| `CopyText` | 所有标识、地址、密钥一律可点击复制 |
| `SaveBar` | 表单有未保存修改时从底部浮起，提供“放弃 / 保存” |
| `Spark` / `AreaChart` | 自绘 SVG；单调三次插值不过冲；**缺口不连线、不补零** |

图表自绘而不用 recharts 一类库：体积小、能精确控制缺口语义（与后端“缺值保持为空”一致）、能和主题令牌直接联动。

## 10. 页面模式

### 10.1 通用结构

```
页头：标题 · 一句话说明 · 主操作（右侧）
工具栏：搜索 · 分段筛选（带计数） · 节点选择 · 刷新
提示区：部分节点读取失败 / 待处理事项（仅在有时出现）
主体：卡片网格或表格
```

页头说明只写“这里是什么、有什么约束”，比如防火墙页写明“外部修改会被恢复到已确认版本，运行规则变更需在期限内确认”。这一句话替代了一整页帮助文档。

### 10.2 各页要点

- **概览**：问候语 + 在线数 + 进行中操作数作为一句话摘要；四个 KPI（CPU、内存、磁盘、网络）带实时火花线；“需要注意”区只在有待确认操作或离线节点时出现；节点卡片默认按“离线在前、本机优先”排序，因为巡检时最先要看的是有问题的。
- **节点**：表格 + 内联 CPU / 内存条；添加节点是三步式对话框（命名 → 生成命令 → 说明后续），接入命令可切换 curl / wget，参数做 shell 单引号转义。
- **节点详情**：四个仪表（环形 + 火花线）常驻顶部，页签切换概况、配置、公网地址、节点账号。配置修改采用“草稿 + 底部保存条”，只提交改动过的字段（merge-patch）。撤销节点放在单独的危险区卡片里。
- **容器**：按节点分组的表格；行内只放最常用的启停 / 重启，其余进菜单；正在执行操作的行状态徽章变为“执行中”并禁用动作，避免重复提交。日志侧板支持跟随、200 / 1000 行、已加载内容内查找、滚动离开底部时暂停自动滚动。
- **防火墙**：顶部四格状态（后端、应用状态、配置版本与已确认版本、最近检查）；规则列表可拖拽排序（拖动手柄而非整行，避免误拖）；编辑对话框实时显示规则的自然语言描述；“接纳现场配置”先预览再提交。集群互信是独立视图。
- **数据库**：集群卡片显示成员健康点阵；新建集群是“填写 → 预览 → 确认”两步向导，预览的阻断项直接禁用提交；只选两个成员时提示多数派风险。账号密码提供随机生成。
- **终端**：多标签；会话在切换页面时保持连接（xterm 实例在模块级保存，只移动 DOM 宿主）；关闭已连接的会话需要确认；断开后遮罩提供“重新连接”。
- **定时任务**：带行号的脚本编辑器（Tab 插入两个空格）；常用计划预设；cron 表达式实时翻译为中文描述；执行记录侧板内直接查看执行日志。
- **操作记录**：按模块与节点筛选；详情侧板展示步骤、错误、日志，“技术详情”折叠显示操作 ID、请求键、队列序号。
- **设置**：左侧子导航（共享布局指示器）；账号修改需要当前密码且成功后重新登录；令牌创建后一次性展示完整值，并给出 curl 与 Prometheus 示例。

## 11. 文案

- 全中文，短句，不用感叹号，不用“您”。
- 按钮用动词：“添加规则”“确认保留”“核对原请求”，不用“确定”“提交”。
- 状态用名词或形容词：“已受理”“执行中”“待确认”“需处理”“已回滚”。
- 提示说清楚后果而不是重复动作：“目标节点会恢复到变更前的已确认配置”，而不是“确定要撤销吗？”。
- 不写营销语和教学段落；需要解释的约束放在页头一句话或字段提示里。
- 错误显示后端 Problem 的 `detail`，前端只为缺少正文的状态码补默认文案。

## 12. 可达性

- 全部交互元素可键盘到达；焦点环使用强调色 2px 外描边。
- 图标按钮都有 `aria-label`；分段控件与页签使用 `role="tablist"` / `role="tab"` / `aria-selected`；对话框 `role="dialog"` + `aria-modal`；开关 `role="switch"` + `aria-checked`。
- 通知区 `aria-live="polite"`，错误通知 `role="alert"`。
- 状态不只靠颜色：每个状态点旁都有文字标签。
- 尊重 `prefers-reduced-motion` 与 `prefers-color-scheme`。

## 13. 性能与体积

- 首屏只加载外壳、概览、公共组件、React、Motion、TanStack Query；其余 12 个页面按路由懒加载。
- xterm（约 330KB）单独分块，只在打开终端页时加载。
- 构建产物合计约 1.4MB（gzip 约 0.4MB），其中字体约 0.3MB。gpt2 内置约 28MB。
- 周期刷新在页面隐藏时停止；操作追踪循环在没有进行中操作时自动停止。
- 列表使用稳定的 key（节点 / Engine / 容器 ID 组合），刷新时不重建 DOM。

状态分三类，各有归属：

| 类别 | 放在哪 |
|---|---|
| 服务端数据 | TanStack Query（只读缓存，靠失效刷新） |

## 15. 扩展指南

### 15.1 新增一个页面

1. 在 `pages/` 新建文件，导出同名组件。
2. 在 `app/App.tsx` 用 `lazy` 注册路由。
3. 在 `app/nav.ts` 加入口（图标、标签、快捷键提示、命令面板关键词）；如果是新的一级路径，同步服务端页面白名单（见 3.4）。
4. 在 `app/queries.ts` 加读取钩子，确定刷新间隔；在 `app/query.ts` 的失效映射里登记对应的 SSE 资源名。
5. 页面使用 `PageHead` + `toolbar` + `Card` 的通用结构。

### 15.2 新增一个写入

```ts
const action = useCommand<Input, Operation>({
  label: '动作名称',          // 用于提示、操作坞、待核对
  node: targetNodeId,          // 原请求回执按此节点查询
  run: async (input, key) => (await call<Operation>('POST', path, { key, body })).data,
  onConflict: () => void query.refetch(),   // 版本冲突时重新读取
});
```

检查清单：

- [ ] 接口要求 `Idempotency-Key` 的，`run` 里传 `key`；不要求的不传（结果未知时会自动走“重新读取”分支）。
- [ ] 配置类写入带 `If-Match`，新建已知 ID 带 `If-None-Match: *`，actions 类带 `expected_revision`。
- [ ] 返回 202 Operation 的，确认 `lib/status.ts` 里有该 `subject` / `action` 的中文名。
- [ ] 不可逆动作前用 `confirm()`；影响面大的加 `typeToConfirm`。
- [ ] 进行中的对象在列表里显示“执行中”并禁用动作（参考容器页 `useActiveOp`）。
- [ ] 不在任何地方写“失败后自动重试”。

### 15.3 新增动效

- 先问“它解释了什么变化”，答不出来就不加。
- 用 `ui/kit.tsx` 已有的弹簧与 `itemVariants`，不新增随意的参数。
- 自定义变体对象要标注 `Variants` / `Transition` 类型，缓动数组用 `as const`，否则 TypeScript 会把它推断成 `number[]`。
- 在“减少动态效果”下检查一遍。

### 15.4 修改视觉令牌

只改 `styles/tokens.css`。新增颜色必须同时给出深浅两套值，并确认语义色与强调色在任意色相下都不撞色。

## 16. 刻意不做的事

| 不做 | 原因 |
|---|---|
| 失败自动重试写入 | 可能导致 root 操作重复执行 |
| 结果未知时“换个请求键再试” | 违反后端幂等契约 |
| 把 SSE 事件当数据渲染 | 事件可能合并、丢失，只能作为失效信号 |
| 前端推算后端没给的状态（如从步骤猜动作名） | 旧记录缺值时保持“未知”，与后端约定一致 |
| 数据刷新闪烁高亮 | 3 秒一次的高亮是噪音 |
| 引入组件库 | 动效与浮层栈需要完全可控 |
| 打包中文字体 | 体积代价远大于收益 |
| 仪表盘自定义拖拽布局 | 运维控制台的价值在一致性，不在个性化 |
| 多套主题风格 | 一个强调色色相 + 深浅两套已经覆盖个性化需求 |
| 在 t1 里重做低频高风险流程 | 交给内置界面，避免仓促实现 |

## 17. 已知局限与后续方向

**局限**

- 本界面在开发过程中完成了类型检查与生产构建，但浏览器交互只经过人工抽查，没有自动化浏览器测试。
- 在 Windows 本地测试后端下，终端、Docker、防火墙、数据库无法真实验证，需要在 Linux 多节点环境验收。
- 第 3.3 节列出的低频流程（数据库接入与扩容、代理路由、集中监控部署、OPSD 共享数据管理）暂无界面。
- 菜单顺序偏好（`/settings/navigation`）尚未提供编辑界面。
- 节点列表分页最多读取 20 页（每页 100）；超大集群需要改为虚拟滚动和服务端搜索。
- 命令面板的容器搜索依赖容器列表已加载；节点很多时首次打开可能结果不全。
- 防火墙规则的“按地址族、作用域”筛选尚未提供。
- 实时缓冲只在当前标签页内存中，刷新后重新积累。

**后续方向**

- 用 Playwright 覆盖登录、命令面板、操作坞、待确认倒计时、Esc 分层、结果未知核对等关键路径。
- 补齐第 3.3 节的低频流程：数据库接入、添加成员与代理、代理路由预览与应用、集中监控部署、OPSD 共享数据管理。
- 为 t1 建立页面级 Playwright 检查（`scripts/check-themes.mjs` 目前只覆盖主题、恢复与会话路径）。
- 概览增加“最近 24 小时变化”摘要（基于 `/monitoring/history`），把“有没有事”扩展到“最近有没有事”。
- 大列表虚拟滚动。
