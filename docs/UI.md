# UI 规范

默认控制台为 `frontend/gpt2`，采用 React 19、Appica 1.3，视觉约定见 [gpt2 设计](../frontend/gpt2/DESIGN.md)。组件从子路径导入，颜色、边框、圆角和交互使用 Appica 角色变量。本文保留通用业务交互约定；旧前端的具体尺寸作为参考。

## 布局与文字

- 侧栏 256px，可收起至 80px；顶栏 64px，900px 以下使用导航抽屉。终端 Provider 保持原挂载位置，响应式变化通过 CSS 完成。
- 各路由使用显式 `page-stack`；页头到内容、独立模块之间为 24px，639px 以下为 20px。工具栏、读取提示、结果及分页使用 `content-stack`，间隔 16px；相邻控件 12px。
- `Heading` 内的返回按钮与标题同行，元信息在标题下方，操作对应标题行；外距由所属页面管理。有标题的面板将标题与正文分开，间隔 16px；正文内距为 24px，639px 以下为 16px。详情网格不再重复添加外层内距，无标题表格使用单层面板。
- 正文和表格为 16px，辅助文字沿用设计系统的标签与元信息尺寸。数字使用等宽数字，完整标识、命令和地址保留读取与复制能力。
- 标签到控件、详情标签到值均为 8px，普通字段间隔 20px，分组间隔 24px；短表单限宽，配置表单使用响应式双列。
- 表格统一单元格留白、分隔线与悬停，操作列右对齐，数值右对齐；横向滚动限制在表格内。

所有业务页签沿用 Appica，统一由 `tab-set` 管理附加样式。点击行高 48px、文字 16px、页签间隔 24px，内部文字层不再叠加垂直内距；页签行到内容为 16px。`TabSet.context` 区分页面、面板、弹窗和排行；排行点击行保持 44px。窄屏只横向滚动，保留受控值、URL 参数、键盘及按需加载。

资源名称菜单使用约 352px 宽度，并覆盖触发器宽度、受视口约束；状态和地址族菜单保持紧凑。选项为选中标记预留固定区域，长名称换行，选项本身不随列表高度压缩，长列表纵向滚动。上下箭头为 Appica 的 `select-scroll-up/down`，随实际滚动显示。

防火墙顶部固定两层。第一层只放目标节点与地址族，节点最大 24rem、地址族最大 12rem，字段间距 16px，低于 640px 纵向排列。第二层左侧保留后端、应用状态与检查时间，右侧放刷新与设置，两组垂直居中，按钮保持 44px；低于 640px 时状态在上、操作在下，两组左对齐。两层间隔 16px，分隔线位于第二层底部，错误提示单独排在其后。服务停用时显示停用状态；默认入站值留在编辑表单。分类页签与规则操作位于表格上方，窄屏换行。行操作保留查看，编辑、排序、删除放入更多菜单；空备注列隐藏，地址支持复制。

互信按来源节点分行，列为来源节点、IPv4、IPv6、操作；地址族筛选同时限制列与状态。地址旁显示实际状态，双栈结果不同时显示部分生效，检查时间集中显示。错误在详情中按运行和永久配置呈现。防火墙设置按目标节点展示双栈状态与汇总；开启确认说明互信公网 IP 优先放行全部主机入站端口，包含数据库端口及共享公网 IP 的其他来源。

## 状态与交互

主导航默认依次为概览、节点、容器、数据库、存储、防火墙、工具、设置。“设置 → 外观”用上移、下移、恢复默认和保存调整八个菜单；桌面侧栏与移动端抽屉共用账号已保存顺序。工具和设置只展开当前分类，父项使用较强文字，当前子页面使用选中背景；子项取消竖线，文字起点与父项一致。收起侧栏后隐藏子项，由一级图标显示当前分类。终端会话使用较轻背景和细边界；名称可收缩并省略，关闭按钮固定 44px，完整名称保留可访问名称与标题提示。其他会话更新时保留未提交编辑，版本冲突后重新读取再保存。“存储”独立页面当前显示未接入。

“设置 → API”提供独立开关、令牌列表和单表单创建；模板预填名称与权限，资源范围紧邻所属模块，有效期和来源 IP 放入可选设置。生成结果一次展示完整值，并提供地址、验证命令及 Prometheus 配置。列表菜单包含编辑、停用、重新生成和删除。

“数据库”按集群展示可用成员、代理与连接数；详情分为概览、成员、库、账号、代理和备份。接入表单完成节点选择、实例发现、连接补充和关联确认。库及账号表单直接选择所需代理，删除使用现有确认框；反馈沿用操作抽屉，展示各步骤与重新处理入口。节点自用 CouchDB 的分组名称为“OPSD 数据”。

数据库列表与详情共用 `database-state.ts`。健康依据 Galera 成员，代理单独汇总；`read.state` 表示读取过程，服务结果仅来自有效结果。首次等待、没有可确认的结果时显示“— / 总数”。正常后台刷新继续显示最近确认的健康、数量和实际采集时间，不显示“读取中、待更新、上次结果、待确认数量”。只有完整 Galera 字段或同次采集的服务结果支持时才确认健康；错误对象优先于读取状态，保留读取故障与明确异常。关联不一致保留错误，只读状态单独表示写入能力。采集时间取成员 `read.data_at`，汇总使用最早有效值，不使用外层 `checked_at`。

健康与库、账号、代理分类查询分开。列表与详情仅更新已有健康缓存，按节点、实例、`data_at` 和 `attempted_at` 比较；保留其他列表行和分类结果。详情在分类页继续每 10 秒读取一次健康，不逐成员加请求。进入或手动刷新后，排队、读取和过期结果最多快速重查 5 秒，间隔 500ms；之后恢复 10 秒，读取错误不进入快速重查，页面隐藏后停止周期刷新。展示不放宽写入条件。

操作记录以 `subject` 的中文业务名称、当前缓存中已知目标、节点、时间和结果组成摘要，不为名称逐条加查询，也不从 ID 或步骤猜测具体动作。详情先展示业务结果、目标、节点、时间、错误、非空步骤和可用操作；执行日志通过独立页面阅读，仅 `task_run`、`container`、`compose` 显示入口和请求日志。日志读取失败单独表达，不能改变业务操作结果；完整操作 ID、资源 ID、请求键等在可展开的“技术详情”中保留复制。当前资源名只辅助定位，不作为历史名称。“结果待核对”独立保留原请求及原资源入口。

容器、Compose 和任务的现有筛选集中排列。容器搜索宽屏优先占用 240～320px，状态和节点按内容限宽；1280px 起同排，640～1279px 两列，搜索占满首行，低于 640px 纵向铺满。控件保持 44px，筛选、读取提示、表格及分页间隔 16px。正常读取过程不显示横幅；真实错误合并当前筛选范围内的节点名称，保留错误、离线、超时、不可用及 Docker 故障，即使读取状态为 stale 仍优先检查错误对象。首次等待与成功空集合分开，容器每三秒、Compose／任务每五秒重新读取；进入或手动刷新后的正常等待可每 500ms 重查，最多五秒。隐藏页面停止周期读取，HTTP 429 沿用客户端等待。未知受理结果提供“查询原操作”，容器需处理操作提供“核对状态”；后台轮询保留当前内容。

`ui.tsx` 提供 PageToolbar、FormSection、StatusLabel、BusyButton、Failure、Confirm 和未提交修改保护。连接、配置、实际应用使用各自的业务状态。

首次加载保留字段、筛选和表头；数据位置使用骨架。后台刷新保留旧内容；手动刷新和提交保留动作名称并显示等待。错误提供相邻重试或核对入口。未知写入先查询原操作或目标状态。

操作抽屉最大宽度 42rem，容器详情弹窗最大宽度 52rem，并受视口约束。对话框与抽屉采用 Header／Body／Footer；长内容在 Body 滚动，提交按钮通过 form 关联表单。确认框宽度 max-w-md，短表单 max-w-lg，规则和操作详情 max-w-2xl。关闭按钮使用中文名称，焦点由 Appica 管理。

业务编辑器通过 `editor-form` 管理 20px 字段间距。编辑节点的正文只放名称表单；Footer 左侧使用红色文字撤销按钮，右侧并排放置取消与保存，窄屏保持单行。撤销按钮独立于名称表单并保留原确认框。底部按钮保持在 Footer，外层弹窗不重复滚动。

页面只呈现字段、选项、操作、业务数据、必要状态与风险确认。公网缓存保留时间和已保存状态；缓存表单禁止提交。

执行日志使用 `/tools?view=logs&operation=…`，容器日志使用 `/containers?view=logs&node_id=…&engine_id=…&container_id=…`，兼容当前后端固定页面路径及内置恢复基址。返回保留来源筛选与所选记录，直接访问和刷新可用。正文占据页面余下空间，独立滚动；默认自动换行，支持搜索已加载内容、上下匹配、复制、手动刷新、自动刷新开关和跳到末尾。刷新仅在可见页面执行，阅读历史内容时保持位置。执行日志按字节追加、合并后解码；容器日志保留 200／1000 行和截断提示。两类日志共用控制序列清理，读取失败保留正文、提供重试，原始错误和请求 ID 位于错误详情；失败与“暂无日志”互斥。

终端在同一状态位置依次显示加载、连接和已连接，正常阶段使用中性色；正文不重复显示加载提示。资源载入失败提供重新加载：失败字体重新读取，失败脚本重新打开当前节点入口。连接故障提供重新连接；多会话、跨页输出、独立票据和输入不重放保持原有契约。

## 检查范围

覆盖登录、概览、节点列表与详情、防火墙、设置和相关浮层；检查浅色、深色、系统主题，320／768／1440px、200% 缩放、长名称、IPv6、键盘、错误、空数据与等待状态。防火墙另查 639／640px 换行边界、1000px 中等宽度及 1920px 宽屏，分别核对筛选字段、状态与操作的对齐关系，并覆盖状态换行、加载和错误。实际结果见 VALIDATION.md。

## 后端交接：数据库读取与操作摘要

六项后端契约已在工作区实施，HTTP 类型由 OpenAPI 生成，验证进度见 [验收](VALIDATION.md)。

| 内容 | 当前契约 |
|---|---|
| 服务与读取 | `status.state/error` 保存最近服务结果；`status.read` 独立保存进度与故障，冷缓存服务结果为 unknown |
| 时间 | 外层 checked_at 为响应时间；read.data_at 为实际采集时间，缓存返回保留来源时间，汇总取最早有效值 |
| 操作摘要 | 受理时保存 action 与 target_name，改名或删除后历史保持原值；旧记录缺值保持未知 |
| 完整引用 | resource 包含类型、所属节点与 ID，容器另有 engine_id；列表、详情与原键查询使用同份记录 |
| 读取故障 | stale 保留 error、timeout、offline；旧数据继续显示，成功刷新解除读取故障 |
| 日志 | supports_logs 表示能力；不支持、成功空日志与读取失败分别呈现，原业务结果保持独立 |

代理页分别展示管理连接、配置一致性、写节点、备用写节点、排序依据、采集时间和跨代理连接预算。路由配置先展示后端地址与差异，编辑后重新预览再应用；未知应答查询原操作。防火墙的“预览当前配置”读取实际后端，接纳操作核对原指纹后保存确认状态。
