# 架构

`backend/cmd/opsd` 是唯一程序入口。Go 模块和内部包统一位于 `backend/`，模块名及导入路径保持不变。普通用户节点通过认证 Noise 通道管理成员、配置、目标队列、监控和可选控制台；root 执行器只监听本机 Unix Socket，接受类型化操作。

`frontend` 是唯一前端,并作为默认内置界面。内置构建以绝对资源基址直接输出到 `backend/internal/webassets/artifacts`，由 `webassets` 嵌入程序；独立主题仍以相对基址构建。OpenAPI、生成配置和共享 TypeScript 类型位于根 `api/`，根 `scripts/` 调度生成与构建。前端接入尚待完成的交互见 [前端开发](../frontend/README.md)。

## 数据与执行边界

所属节点 SQLite 保存身份、配置、账号、成员目录、队列与待上传记录。现有 Galera 集群的 `opsd_core` 保存成员权限、共享策略、数据库定义、跨节点流程、请求回执及签名历史；每节点通过本机 ProxySQL 访问。目标操作在本机持久受理后按资源调度；控制台、入口或共享数据库停止时，本机操作与恢复继续。

节点和执行器数据库共用编号 SQL、事务和版本记录。节点首次版本化在同一事务登记现有结构，保留原身份、账号、队列和记录；高于程序支持的数据库版本拒绝写入。防火墙检查时间更新最新观测，配置、结果或错误改变时才追加签名历史。上传确认后的本机重复状态每次最多整理 200 条，保留每次实际变化的首条、连续状态的最新一条及未上传资料；进度与删除在同一事务提交，共享历史保持原内容。

菜单顺序绑定所属节点的管理员账号，保存在独立的 `account_navigation` 表，版本与账号凭据分开。修改通过本机事务保存并向当前控制台会话发送 SSE，账号改名、改密及重启后保留；其他节点的管理员独立保存各自顺序。

`cluster` 负责节点协议和数据；`control` 负责会话、HTTP、SSE；`apiauth` 负责令牌摘要、生命周期与权限；`executor` 负责 root 服务；`operations` 负责独立执行与恢复；`firewall` 负责原生后端；`dockerengine` 负责本机 Docker；`databaseengine` 负责本机 MariaDB／ProxySQL；`monitoring` 负责采集。协议定义位于 `protocol`，HTTP 类型只从 `api/openapi.json` 生成。

`consoletheme` 管理当前节点的完整静态前端包，`control` 继续负责认证、资源路由及独立内置界面。主题文件位于节点数据目录，安装与选择经本机 SQLite 保存，不进入成员目录、共享历史或 root 执行器。包格式、切换和中断恢复契约见 [控制台主题](THEMES.md)。

防火墙后台检查在请求期限内等待本机操作锁，锁繁忙时保留上次实际状态；实际读取失败单独记录错误。普通防火墙配置与互信分别保存责任，原生后端写入取得短时锁；容器使用 Engine、项目和容器资源锁。检查完成后继续按确认配置和实际互信覆盖受理迁移。

操作受理事务同时保存具体 `action`、当时的 `target_name`、类型化 `resource` 和 `supports_logs`。容器引用包含所属节点、Engine 和完整容器 ID；历史读取保留受理时名称，旧记录缺失信息保持未知。日志读取独立返回不支持、成功空日志或读取故障，业务操作结果保持原值。

### 数据类型与权威来源

每类数据只有一个权威来源。同一类数据在**绑定前后**的权威可能不同，下表分别注明；
"副本"一列写清副本的用途，副本不构成写入来源。

| 数据类型 | 绑定阶段与范围 | 权威来源 | 写入方 | 副本与用途 |
|---|---|---|---|---|
| 成员身份、公钥与地址 | 入群签发时绑定，随签名成员目录分发 | 签名成员目录（各成员私钥签发，其他节点验签） | 成员自身签发 | 各节点本机 SQLite 保存目录副本，用于调度与拨号 |
| 数据库定义、受管策略、代理关联 | 绑定前随签名目录分发；生效后以共享库为准 | 生效前：签名目录；生效后：共享 SQL `opsd_core` | 控制面经版本化迁移写入共享库 | 本机 SQLite 保留读取副本，供本机代理与读取路径使用，不作为写入来源 |
| 账号、菜单顺序、本机队列、待上传记录 | 受理时绑定到所属节点 | 该节点数据目录 `/var/lib/opsd/node` 的本机 SQLite | 该节点自身事务 | 不设跨节点可写副本；待上传记录只在本机排队 |
| 本机操作与恢复记录 | 执行时绑定到本机执行器 | `/var/lib/opsd/executor` | 执行器 | 无副本；节点重建后允许丢失 |
| 监控原始与汇总归档 | 采集后绑定到对象存储 | S3 桶内对象 | 采集侧写入，Compactor 压实与保留 | Store 与 Query 只读；本机目录仅作待上传缓冲 |
| 前端包与主题包 | 安装或切换主题时绑定到节点 | 构建产物 + 节点数据目录 | 安装器与主题切换操作 | 内置恢复界面是独立副本，不随主题切换失效 |

## 通信与当前读取

节点通信协议版本与本机持久操作契约分别维护。认证握手只确认成员，首次加入携带完整目录；常规目录交换按签名对象摘要发送差异，相同内容跳过事务、验签及维护通知。四个邻居并发交换并错峰调度；同目标合并拨号，签名成员记录携带按优先级排列的 ET／公网备选端点，逐个拨号并校验同一节点身份；请求应答未知时换路后查询原操作。空闲连接保留六十秒，按需提升常驻，常驻最多八条、总计三十二条。

接收循环持续分发应答，普通业务与操作查询、确认、取消和恢复使用独立有界队列及字节预算。Noise 加密记录携带消息编号、总长和偏移，消息按记录交错发送，大结果不会独占整条通道；接收中的消息数及总字节受限。本机执行器的控制请求与批量读取分别使用连接名额。

概览、当前监控、容器和数据库状态由入口节点共享刷新。HTTP 返回已有值及 `read.state`、数据时间、尝试时间和错误，首次排队不会显示离线；每个目标从实际取得读取名额起计算期限。页面停止请求后刷新任务结束。概览和容器的目标间隔为三秒，历史采集与当前读取独立，旧值保留时间且不计入当前有效汇总。

服务健康保存在 `status.state/error`，读取进度与错误保存在 `status.read`；冷缓存的服务结果为 `unknown`。过期判断保留 `error/timeout/offline`，成功刷新解除读取故障。缓存期限使用接收端完成时间。`read.data_at` 使用实际数据采集时间，重复返回缓存保留该时间；外层 `checked_at` 为响应生成时间，汇总采集时间取最早有效值。

历史从共享 SQL 按来源、种类及时间读取签名记录，验签后归并时间桶，图表最多约七百二十个点，缺口继续为空。采集、上传和共享维护分别调度。

旧 CouchDB 仅在迁移前沿用原有上传与维护，绑定共享库后停止旧写入，历史留作导入来源。本机队列继续独立运行，积压在共享数据库恢复后上传。

## 共享存储、协调与恢复

`sharedsql` 只负责 InnoDB 共享事务、版本条件更新、回执、流程与签名记录；SQL 管理及 ProxySQL 适配留在 `databaseengine`。`executor` 通过 `protocol` 交换存储及类型化执行消息，保持对节点实现的单向边界。事务提交后再调用远端节点或宿主机动作。

共享表使用明确主键与唯一约束；实际 Galera UUID 对应一个有效数据库定义。管理事务先取得共享授权版本锁再核验成员资格，关键读取使用 `wsrep_sync_wait=1`；互信策略通过共享事务检查版本并更新，本机公网地址按所属节点的签名版本补传。明确回滚的事务冲突最多重试三次；提交应答未知返回原请求查询入口。服务账号仅授予精确 `opsd_core` 的 SELECT／INSERT／UPDATE／DELETE，正确转义库名中的 `_`；结构初始化使用本机维护步骤。每节点普通连接池上限为 2，新代理对每个后端上限为 2，监控账号上限为 4；复用代理保留业务限制，接入核算时对同一代理的重复主机组端点去重并保留管理连接余量。

全部使用新代理时，4／10／40 节点对每个后端的共享与监控连接预算分别为 24／60／240，再保留 2 个管理连接；这是配置上限核算。复用业务代理按现场连接上限计入总量，超过数据库上限时停止接入并报告。

初始化固定数据库绑定、所有节点接入资料、共享密钥与迁移来源，本机密文保存阶段和游标。迁移期间暂停共享写入及旧数据库流程，按原 ID 导入成员、策略、定义、请求回执、固定步骤、本机签名记录与 CouchDB 历史；同版本内容冲突停止。目录与自身发布在同一加入事务中提交，共享绑定也一并保存；共享数据库定义在代理就绪后从 SQL 取得。导入后核对目录与待上传记录，再切换为 active；旧资料保留供核对。

新成员先经现有成员取得授权和仅由所属节点解密的接入资料，再准备本机代理。账号完成状态保存在共享库，后续引导复用原密文；原维护节点离线后，其他成员继续提供已完成资料。本机代理就绪并通过共享连接读取后，节点状态才显示已连接。

共享流程提交时固定参数、目标、步骤与子操作 ID，请求回执与流程同事务提交。协调节点持有十五秒租期并保存协调代际；备用候选以条件更新接管，先查询原目标步骤，复用已完成结果，明确未受理的步骤才提交。目标受理时校验并保存代际，已受理步骤独立执行。旧协调节点恢复后释放本机待执行副本，读取新归属。控制台关闭后保留已登记候选资格，主用与备用入口配置单独保存。

节点 SQLite 持久保存目标受理序号、资源声明、确认配置与恢复资料，执行时取得跨进程锁。容器按 Engine／项目／完整容器 ID，Compose 项目覆盖其容器，数据库按集群与实例、部署另占目录及端口，Shell 按任务 ID。等待、人工处置和未知结果保留相关资源责任；父流程等待子步骤时释放执行名额，无冲突操作继续。

执行器完成旧进程隔离与必要防火墙恢复后提供查询入口；数据库等待交给独立操作服务。服务启动失败保存错误，由执行器重调度原 ID。每节点代理独立保存策略版本、排序和执行进度，数据库成员变化后分别应用；离线节点恢复后补齐。代理异常恢复原容器，内存／运行／磁盘配置逐层应用并读回，保留其他账号、规则、主机组及活动事务。

共享库整体不可写时，最后确认的成员权限继续用于可达节点本机操作，成员变更、协调转交和新的共享步骤暂停；恢复后先同步权限与版本。撤销成员同时清理各本机代理账号、数据库服务账号及已有连接，代理等待连接实际终止后读回。所属节点收到自身撤销记录后关闭共享连接，保留本机查询和恢复入口。旧节点数据恢复先核对共享记录序号与原操作结果，通过 `opsd data recover` 恢复；旧管理协议节点拒绝共享写入。节点私钥、登录会话与原始日志留本机。


## API 与授权

唯一业务入口 `/api/v2` 的类型、方法、身份、授权解析、并发条件与分页声明以 OpenAPI 为源，生成严格接口和运行时授权定义。HTTP 层校验请求并统一 Problem、请求 ID 和媒体类型；响应在现有业务测试中按同一规范核验。SSE、WebSocket、ZIP 和指标保留专用处理器，仍登记契约。在线 Swagger 使用随程序嵌入的资源，完整规范要求认证。

API 和网页分别启停，共用现有 Web 监听；两者均关闭释放监听。成员通信、本机控制 Socket 与恢复进程独立运行。携带 Authorization 请求头时始终使用令牌认证；浏览器会话继续检查 CSRF。敏感管理接口仅接受管理员会话。

令牌所属节点保存随机值的摘要、授权与版本。任意入口每次请求经认证成员通道向所属节点核验一次，批量读取复用请求内结果；停用、过期、重新生成及撤销影响后续核验。所属节点离线返回 503。授权模块集中采用默认拒绝，列表先过滤再分页或汇总；地域范围按当前成员归属计算，节点与集群范围使用稳定 ID。

受理写操作固定服务端派生的调用身份、目标及参数；幂等范围为稳定账号或令牌身份、目标与请求键，重新登录与跨入口保持身份。异步写入复用队列，同步创建与最小请求回执在所属 SQLite 同一事务提交，秘密只保存摘要。回执查询继承原资源权限；未知应答只查询原键或原操作，不换键补发。查询、取消、确认、重新处理和接受现状继承原操作的模块与资源权限。已持久受理的操作按固定参数继续，令牌撤销后拒绝新请求。

配置 GET 提供不受运行检查时间影响的强 ETag，CRUD 条件由所属节点核验。异步受理固定预期版本，执行前再次核验；受理后的冲突保存到原操作。列表按授权范围过滤后分页，跨节点游标保留各目标已返回位置，不可用目标不推进；操作按创建时间和 ID 降序，目标队列序号继续表示受理顺序。旧历史 JSON 保留原样。

任务与 Compose 使用独立模块授权，任务 read 只提供元数据，脚本定义与执行要求 `tasks.manage`，该权限可执行任意 root Shell。旧令牌不自动增加模块。节点声明 `api_authorization_version: 2`；缺少新增身份及授权语义的节点拒绝对应写入。

当前指标复用三秒共享刷新与本机采集合并，当前汇总按有效值计算。离线项保留最后采集时间。JSON 提供必要身份、读数、可达状态与检查时间；Prometheus／OpenMetrics 指标按监控、容器、数据库各自权限生成。历史继续每五分钟采集、保留七天；多节点查询可按节点返回，共享库故障单独报告历史不可用。

## 数据库管理

集群定义与协调代际保存在共享库，未绑定阶段沿用签名成员目录；本机实例凭据及其历史版本只保存在所属节点 SQLite，密码使用现有密文机制。公开 HTTP 结构保留必要连接身份及状态。发现仅读取固定私有配置字面值与本机 Docker 配置；执行器只接受本机回环地址或绝对 Unix Socket。

数据库读取分为健康摘要、库、账号权限、代理及备份。列表和成员只读取健康摘要，详情由页签请求；健康缓存五秒，详情三十秒，缓存期限从完成时间计算。SQL 连接按实例及凭据版本有界复用，写入前的身份、权限和实际状态直接读取。带内容哈希的静态资源长期缓存，会话活动时间每六十秒合并写入；SSE 按事件批次合并前端刷新。

数据库写入创建共享流程并由当前协调节点推进，目标步骤进入所属节点持久队列。受理时固定集群版本、合格成员及所选代理的连接版本；Galera 身份、Primary、Ready、Synced 与只读状态在执行前再次核对，业务变更执行一次。数据库层保护系统库、全局特权账号和登记的管理、监控、备份与 SST 账号。

创建、接入、添加成员和添加代理共用部署预览与原操作队列。扫描仅读取，按实际 Galera UUID 分组，代理按后端端点提供关联候选；确认后登记，重复接入复用已有集群。扫描跳过停止或已移除的容器；提交时再次核对实际运行状态，已登记实例的停机状态由原集群详情展示。预览计划绑定操作者、版本和三十分钟期限，使用协调节点公钥加密；提交保留原请求键。共享协调进度使用授权成员共享密钥加密，本机执行副本按本机密钥加密；所属节点保存连接凭据和实际执行记录。

部署由 `databaseengine` 生成固定版本模板、检查空目录、端口和磁盘，`dockerengine` 使用本机 Docker API；Debian／Ubuntu 缺少 Docker 时通过本机软件包管理器安装，已有服务直接复用。复制使用 TLS；扩容读取已有成员实际镜像、端口、同步账号和证书，缺失资料进入预览阻断项。必要防火墙规则限定成员地址及实际端口，使用原配置、读回和确认流程；执行时检查成员连接。首次启动前持久写入 bootstrap 意图，后续启动走正常入群。同步作为独立等待步骤，实际身份一致且 Primary／Ready／Synced 后逐个登记，最后更新已启用的受管代理策略；后续失败保留已完成成员。已有数据目录、配置和数据库转换留在独立操作范围。

创建及扩容完成后，通过持久步骤更新本系统创建实例的重启成员地址；启动脚本从所属状态目录读取，保留原数据库配置。手工部署实例保持原启动配置。保存前核对容器标识及部署定义，文件原子替换并读回；协调节点重启后查询原步骤。已有成员的身份、健康、版本和数据空间需求在执行前再次检查，容器异常重启转为待处理。

`operations` 保存每一步准备状态、发送意图、读回和结果。代理写入依次修改内存、LOAD 到运行、SAVE 到磁盘，前后分别检查三层配置，其他待应用差异保留并返回冲突。删除账号先禁用所选代理，再删除 Galera 账号并清除代理记录。跨节点代理步骤进入目标节点队列，已完成步骤保留；协调节点中断后先查询原步骤，未知写入只读回，显式重新处理后才继续尚未执行步骤。凭据版本变化保留已受理操作所固定的版本。

ProxySQL 可登记在任意 OPSD 节点，包括只有代理的节点。受管策略随集群签名目录保存数据库成员、代理可达 SQL 地址、`10/20/30/40` 主机组及账号关联；首次接管前检查全部有效成员的 `proxy_routing_version` 能力。每台代理本机 SQLite 保存排序、采样结果、已应用策略版本和待处理操作，控制台关闭后继续维护。接管经预览和持久操作执行，移除预览中的退出后端，保留其他主机组；全量 `mysql_servers` 集群同步和相冲突的读写路由保持冲突。

代理每三十秒读取已有监控日志，最近一百二十秒成功样本至少三条、最新样本六十秒内时计算中位数。本机数据库优先，未知延迟保留顺序；远端改善同时达到 20% 和 10ms、连续三轮且距上次主动变更五分钟后调整权重。原生 Galera 监控保持每台代理一个写节点，读写同组，活动事务继续使用原连接。配置无变化时跳过操作与 LOAD/SAVE；外部差异和未知结果暂停自动更新，原请求与步骤先读回，每台代理最多一个待处理自动请求。连接预算合计各代理对同一后端的上限，主机组内重复端点按一次计算，数据库参数沿用现值。

备份页只读取既有计划、执行状态和目录产物。SQL 查询与表数据编辑交给外部工作台。OPSD 自用库与各节点代理在“数据库 → OPSD 数据”管理，旧 CouchDB 保留迁移读取；后续 Silo 归属独立“存储”，低配置节点使用 S3 客户端，跨地域按桶异步复制。

## 容器

容器读取经节点认证 RPC 和类型化执行器消息到达目标本机，官方 Docker Go SDK 依赖留在 `dockerengine`。显式使用本机 Unix Socket 和 API 协商，支持 Linux rootful Docker；控制台及普通用户节点保持现有权限。旧 Portainer 转发方案作为历史设计。

资源由节点 ID、Engine ID 与完整容器 ID 定位，执行前再次检查。启动、停止和重启复用目标队列及独立操作服务，参数不可变；执行意图和 Docker 应答分别持久保存。重启成功要求已记录应答且读回新的启动时间。应答丢失或进程中断后只读回原资源，未知结果进入需处理；人工核对与接受现状保持原操作标识。防火墙的确认期限、定向撤销和确认配置独立运行。

列表按目标合并五秒内读取，日志合并两秒内读取；页面可见时轮询，日志采用有界尾部批次，最多 1000 行、256 KiB，TTY 与非 TTY 按 Docker 格式解码。读取使用限时请求和有界缓存；日志留在请求及短期缓存中。实际容器状态只通过所属节点获取，共享历史只保存操作记录。

Compose 容器允许单容器日常操作；Swarm 任务只读。OPSD 存储容器的启停由现有存储设置负责。Docker 发布端口策略留待后续。

## 公网地址与互信

公网地址按 IPv4／IPv6 独立保存自动或手工模式、确认地址、观测、时间及错误；节点通信 URL 与实际监听分别配置。新安装默认发现公网 IPv4，再尝试 IPv6，显式 `--address` 优先。自动模式启动、网络变化及每五分钟发现；每个地址族总期限八秒，成员观测与公共回显并行，最多三个同族公网成员候选、ipify 主源及 icanhazip 备用源，绕过环境代理。候选失败继续尝试并保留具体错误；来源冲突、发现失败与无对应地址族分别保存。

安装命令使用成员目录公布的通信 URL，保留固定版本脚本和 Noise 公钥。页面只生成下载、执行及短参数；系统准备和版本核验由发布脚本负责。`opsd network` 是持有节点及执行锁的本机维护入口，检查未结束操作，在节点服务停止时更新监听与通信模式，并同事务发布自身成员与配置记录。

一致结果更新地址和确认时间；冲突和失败保留上次地址及确认时间，手工模式保持人工值。所属节点签署地址记录，经认证目录传播。GET 优先读取目标，离线返回缓存标记。保存通信配置校验可确认的监听不匹配，返回 `restart_required`；本机 `opsd network` 在停服并检查未结束操作后更新。通信入站可达性由实际认证连接体现。

互信默认关闭，开关为集群签名策略。版本包含逻辑计数和发布节点 ID；并发同计数优先关闭，再按 ID 裁决。修改检查期望版本。全部有效成员（包含本机）的公网地址生成去重后的主机入站来源集合；共享 IP 保留全部有效关联节点，直到最后一个关联成员撤销或更换地址后移除。

普通节点持久化最新目标，root 执行器另存目标和实际状态，使用独立维护责任及短时原生后端锁：UFW 在 `before.rules`／`before6.rules` 保存自有 `OPSD_PEERS` 地址集合和加载引用，并在双栈 `INPUT` 首条维护带标记的运行跳转。互信来源命中后直接放行全部主机入站端口，其他来源返回现有外部规则及 UFW 普通规则。执行器启动和每五秒核对地址、跳转唯一性与位置，定向修复重复或后移的所属跳转；停用 UFW 时撤除所属运行规则并保留持久目标。原有外部链的内容及相对顺序保持原状。nftables 在可维护 input 基础链保存带标记规则，firewalld 使用自有 ANY→HOST 策略。普通规则导入、编辑与恢复保留互信区域。专用链中的外部规则或未知引用停止该部分改写并报告原因。

状态按地址族、运行与永久范围读回。关闭时撤除自有规则，离线节点恢复后继续；撤除未完成保留列表。Docker 发布端口策略与容器流量互信留待后续。

互信仍每五秒实际核对，规则、状态或错误改变时才通知前端。普通防火墙接纳先预览当前原生配置和指纹，执行时重新读取并核对；成功更新节点与执行器确认记录，现场规则保持原值。指纹排除采集时间、计数器及所属互信规则；预览后外部变化返回冲突，相同失败输入保持原停止重试行为。

本机没有可用公网 IPv6 地址或路由时，自动发现保存“无公网 IPv6”，互信汇总排除该缺失项；已有 IPv6 能力但外部发现失败仍报告错误并保留确认地址。nftables input 基础链省略 policy 时按默认 accept 读取。没有活动 UFW／firewalld／nftables 服务而存在原生 INPUT 规则时，识别为 iptables；普通规则只读。互信独立维护 `OPSD_PEERS` 与双栈 INPUT 首条引用，持久目标保存在执行器数据库并读回 `/etc/opsd/firewall/peer-trust.ipv4.rules`、`peer-trust.ipv6.rules`。执行器启动及维护恢复所属规则，不依赖 1Panel；不启用其他防火墙管理服务。

互信完成实际读回后，普通节点自动选择已管理入站规则中与成员精确 IP 相同、任意目标、任意协议、全部端口的允许条目，通过既有持久队列转交互信。节点在成功前保留原普通配置；执行器核对所需互信版本、运行与永久覆盖、普通确认配置及仅移除匹配条目的差异，按原有操作写锁执行并定向恢复。专用迁移信息仅用于该操作的校验，写入执行器确认配置时清除；`Automatic` 仍只恢复已确认配置。节点收到成功结果后同事务推进普通目标与确认配置。

迁移操作标识由互信版本、普通配置版本及规则集合确定。应答丢失查询同一操作，同输入失败停止自动重试；既有重试入口重新检查当前待迁移集合。迁移状态、操作 ID 及错误随普通防火墙状态保存，并在互信 GET 响应展示。转交后的规则随互信生命周期撤除，原普通条目保持移除状态。

## 终端与任务执行

终端使用独立 Noise 节点数据通道和执行器 Unix WebSocket，不占用业务 RPC 处理名额。入口签发绑定管理员会话的短期单次票据，创建检查 CSRF，连接检查 Origin；目标核对成员身份与撤销。执行器限制 PTY 数量，断连、退出登录或节点停止时释放会话及其作业；原始输入输出不写共享历史。

Shell 任务与 Compose 登记保存在目标 `node.db`。任务按五字段 cron 与 IANA 时区调度，任务保存后通知调度器更新，启动不补跑错过的计划。计划时间构成稳定请求键，同任务禁止重入，总未结束任务最多八个；任务执行与普通系统修改分开调度，任务锁按任务 ID 区分，普通操作使用对应资源锁。脚本进入独立 root 操作服务及 systemd 进程组，取消持久保存后重启原操作服务释放进程组，结果未知只查询原记录，不重放脚本。日志只保存在目标节点并限制大小与分页读取量。

Compose 仅登记实际标签对应的定义目录与文件，执行前重新核对，CLI 只使用本机 Docker Socket。拉取、启停、重建与更新逐步保存意图和结果。单容器镜像更新保存完整私有配置、挂载及网络，先拉取再停止，读回替换结果后移除原容器并保留卷；私有环境变量不进入共享记录。未知结果保留原容器及候选状态，人工重新处理只检查实际结果。

运行时模型请求为零。

同时拨号选择稳定连接时，完成握手的重复连接继续处理已发送请求与应答，空闲后释放；当前与待释放连接共同受三十二条上限约束。节点关闭时释放两类连接。
