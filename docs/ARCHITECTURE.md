# 架构

`cmd/opsd` 是唯一程序入口。普通用户节点通过认证 Noise 通道管理成员、配置、目标队列、监控和可选控制台；root 执行器只监听本机 Unix Socket，接受类型化操作。

## 数据与执行边界

所属节点 SQLite 保存身份、配置、账号、成员目录、队列与待上传记录。地域 CouchDB 保存签名共享记录和历史，数据库内容用于查询与复制。目标操作在本机持久受理后串行执行；控制台、入口或共享数据库停止时，本机操作与恢复继续。

`cluster` 负责节点协议和数据；`control` 负责会话、HTTP、SSE；`executor` 负责 root 服务；`operations` 负责独立执行与恢复；`firewall` 负责原生后端；`monitoring` 负责采集。协议定义位于 `protocol`，HTTP 类型只从 `api/openapi.json` 生成。

## 公网地址与互信

公网地址按 IPv4／IPv6 独立保存自动或手工模式、确认地址、观测、时间及错误；节点通信 URL 单独配置。新安装默认发现公网 IPv4，再尝试 IPv6，显式 `--address` 优先。自动模式启动、网络变化及每五分钟发现；每周期每地址族最多一次公共 HTTPS 回显和一次认证成员回显，绕过环境代理。

一致结果更新地址；冲突和失败保留已有地址，手工模式保持人工值。所属节点签署地址记录，经认证目录传播。GET 优先读取目标，离线返回缓存标记。通信入站可达性由实际认证连接体现。

互信默认关闭，开关为集群签名策略。版本包含逻辑计数和发布节点 ID；并发同计数优先关闭，再按 ID 裁决。修改检查期望版本。全部有效成员（包含本机）的公网地址生成去重后的主机入站来源集合；共享 IP 保留全部有效关联节点，直到最后一个关联成员撤销或更换地址后移除。

普通节点持久化最新目标，root 执行器另存目标和实际状态，与普通操作共用写锁并独立维护：UFW 使用自有 before 链，nftables 在可维护 input 基础链保存带标记规则，firewalld 使用自有 ANY→HOST 策略。普通规则导入、编辑与恢复保留互信区域。外部归属冲突停止该部分改写并报告原因。

状态按地址族、运行与永久范围读回。关闭时撤除自有规则，离线节点恢复后继续；撤除未完成保留列表。Docker 互信留待容器功能接入。

互信完成实际读回后，普通节点自动选择已管理入站规则中与成员精确 IP 相同、任意目标、任意协议、全部端口的允许条目，通过既有持久队列转交互信。节点在成功前保留原普通配置；执行器核对所需互信版本、运行与永久覆盖、普通确认配置及仅移除匹配条目的差异，按原有操作写锁执行并定向恢复。专用迁移信息仅用于该操作的校验，写入执行器确认配置时清除；`Automatic` 仍只恢复已确认配置。节点收到成功结果后同事务推进普通目标与确认配置。

迁移操作标识由互信版本、普通配置版本及规则集合确定。应答丢失查询同一操作，同输入失败停止自动重试；既有重试入口重新检查当前待迁移集合。迁移状态、操作 ID 及错误随普通防火墙状态保存，并在互信 GET 响应展示。转交后的规则随互信生命周期撤除，原普通条目保持移除状态。

运行时模型请求为零。
